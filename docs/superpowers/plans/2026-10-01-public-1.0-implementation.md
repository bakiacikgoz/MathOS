# MathOS genel 1.0 hazırlığı uygulama planı

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Mevcut ürünün güven, kurulum ve veri koruma engellerini kapatmak; gerçek kabul kanıtı olmadan genel 1.0 yayınlamamak.

**Architecture:** Mevcut servisler ve yayın araçları yerinde düzeltilir. İnsan onayı yeni bir insan kararı gerektirir; klon/import sırasında üretilmez. Yayın paketi kaynak kimliğini, gerekli varlıkları, arşiv hash'ini ve doğrulanabilir lisans envanterini birlikte taşır.

**Tech Stack:** Bun 1.4.1+, TypeScript, SQLite, Tauri 2, PowerShell/POSIX shell, GitHub Actions.

**Spec:** [Onaylanan hazırlık raporu](../../1.0-public-readiness-2026-10-01.md). Baki 1 Ekim'de bu planın uygulanmasını istedi. Çalışma yöntemi kullanıcı kuralları gereği Sol alt ajanları ve salt okunur Astra değerlendirmesidir.

## Global Constraints

- Windows 11 x64 ve macOS arm64 kapsamı korunur; erişilemeyen platform NOT_VERIFIED kalır.
- main üzerinde çalışılır; yeni branch/worktree, force push ve erken stable tag yoktur.
- Başlangıçtaki Cargo.lock/Cargo.toml farkları korunur; ilgisiz commit'e alınmaz.
- Gerçek workspace ve kullanıcı model ayarları yerine izole geçici fixture kullanılır.
- Lean/Mathlib bilgisayar başına paylaşılan, pinli otomatik kurulum ve ilk açılış ilerleme ekranı korunur.
- C-001 anlam onayını yalnız Baki tam ifadeleri inceleyerek verebilir.
- Yeni sağlayıcı, yeni OS, yeni UI ve otomatik desktop updater kapsam dışıdır.
- Her değişiklik RED/GREEN regresyonu, etkilenen testler ve bağımsız incelemeyle doğrulanır; son kod adayında tam test çalışır.

## Review Focus

1. Onaysız/rejected/stale kaynak klonu insan onayı veya human-approved olayı üretmemeli.
2. Onaylı kaynağın ismi/context'i değişen klonu da yeni onay beklemeli; import kernel kontrolü korunmalı.
3. Kurulum yalnız executable kopyalamamalı; Atlas/VSIX varlıkları kurulu konumdan bulunmalı.
4. Daha eski/eşit sürüm veya uyumsuz schema normal güncelleme olarak sunulmamalı; kilit/staging hatası çalışan binary'yi korumalı.
5. Dolu eski schema migration/restore sonrasında araştırma durumunu korumalı; daha yeni schema yazılmadan reddedilmeli.
